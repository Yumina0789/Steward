# 0002 不做 Web 终端，只提供白名单动作

## 状态

已接受（2026-10-09）

## 背景

服务器面板最诱人的功能是「在浏览器里敲命令」：一个 `POST /api/exec` 配一个输入框，想干什么都行，实现成本几乎为零。

但它把一台**公网可达的 root shell** 挂在了一个 token 后面。而同一份 token 还躺在浏览器的 localStorage 里、经过反向代理、出现在可能被截屏的页面上。面板本身已经能启停服务、结束进程、封 IP —— 权限面已经很大了，再叠一个任意命令执行，安全模型就从「限制你能做什么」退化成「只要能过认证就无所不能」。

另外这类功能在实现上也很难做对：伪终端、信号、流式输出、断开清理、并发会话，每一项都是独立的坑；做浅了就是个 `subprocess.run` 的包装，做深了等于重写一个 SSH 客户端。

## 决策

Steward 在 v1 **不提供任意命令执行**。取而代之的是一张**白名单动作表**：每个动作是一个名字 + 一段固定的 argv + 说明 + `danger` 标记。用户能触发的只有表里的项。

规则：

1. 动作的 argv 在代码里写死，**没有任何用户输入拼接进命令**；需要参数的（如封禁 IP、看某个单元的日志）参数走严格校验的独立通道，且以列表形式传给 `subprocess`，不经过 shell。
2. 标记为 `danger` 的动作在界面上要二次确认，并**无论成败都写审计**。
3. 想加新操作就改代码、走一次 CI 与部署 —— 这个摩擦是刻意的。

## 后果

- 灵活度换安全：临时想跑一条命令，用面板做不到，得去 SSH。这正是我们想要的默认。
- 白名单会不够用，然后有人想「就加一个 `exec` 吧」—— 要顶住，或者把它做成一个新的、单独鉴权的组件。
- 因为不需要终端，面板不需要伪终端、不需要流式输出、不需要会话管理，实现显著变小。

## 备选方案

1. **通用 Web 终端 + IP 白名单 + 审计**：可行，但 IP 白名单对动态 IP 的家庭宽带等于没有；而它带来的便利，SSH 已经提供了。
2. **终端 + 只允许非 root 用户**：面板要管的服务大多需要 root，降权后一半功能失效，反倒促成「用 sudo 包一层任意命令」的回退，等于没限制。
